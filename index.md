# Глоссарий

Единый словарь языка платформы: процессные и продуктовые термины живут в одном
индексе. Термин **определяется только здесь**; playbook, [замысел
продукта](terms/product-intent.md) (`product-intent`), architecture и
specifications дают ссылку, а не второе определение.

| Термин                                                  | Краткая суть                                                                                                                                                                       |
|---------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [Бизнес-драйвер](terms/business-driver.md)              | Более высокий уровень мотивации, чем цель: почему это важно для бизнеса в стратегическом или операционном контексте — и почему критично именно сейчас                              |
| [Бизнес-цель](terms/business-goal.md)                   | Измеримое намерение продукта: какую проблему решает или какую возможность открывает — ценность для пользователя или бизнеса, а не техническое решение                              |
| [Замысел продукта](terms/product-intent.md)             | Источник правды о смысле продукта: зачем он существует, для кого и какие устойчивые способности предоставляет                                                                      |
| [Stakeholder](terms/stakeholder.md)                     | Заинтересованное лицо: лицо или группа, чьи интересы продукт обслуживает или затрагивает — не обязательно пользователь системы                                                     |
| [Capability](terms/capability.md)                       | Ключевая возможность продукта: класс проблем стратегического уровня, которые продукт умеет решать, и инструменты для стейкхолдеров — не для конкретных пользователей или ролей     |
| [ArchiMate-модель](terms/archimate-model.md)            | SSOT структуры в `architecture`; типовой артефакт — `.archimate` (ArchiMate)                                                                                                       |
| [SCM-платформа](terms/scm-platform.md)                  | Платформа для хранения исходного кода и совместной разработки программного обеспечения, поддерживающая полный цикл — от планирования работы до развёртывания и эксплуатации        |
| [Remote (ремот)](terms/remote.md)                       | Удалённый репозиторий рабочей копии Git, который настраивается командой `git remote`; «remote» и «ремот» взаимозаменяемы.                                                          |
| [Поток выполнения](terms/command-flow.md)               | Последовательность шагов алгоритма одной CLI-команды                                                                                                                               |
| [Реквест](terms/request.md)                             | Единица учёта инициативы в Jira: хотелка, Discovery, трассировка к git                                                                                                             |
| [Ключевой сценарий](terms/key-scenario.md)              | Ожидаемое изменение для стейкхолдера — 1–3 предложения языком сторон                                                                                                               |
| [Изменяемость документации](terms/documentation-modifiability.md) | Документ (или согласованный набор документов) устроен так, что любое изменение содержания можно внести легко, полностью и согласованно, сохраняя принятую структуру и стиль |
| [Discovery](./terms/discovery.md)                       | Дисциплина исследования и формирования понимания                                                                                                                                   |
| [Delivery](./terms/delivery.md)                         | Дисциплина реализации и поставки ценности                                                                                                                                          |
| [Definition of Ready (DoR)](terms/dor.md)               | Набор шлюзов готовности по лестнице артефактов: без чего команда не вправе тратить capacity на следующий шаг; отвечает на вопрос, можно ли начинать шаг (в Discovery или Delivery) |
| [Definition of Done (DoD)](terms/dod.md)                | Общий чек-лист команды для инкремента продукта и каждого элемента бэклога: работа над поставкой технически и процессно завершена и может быть выпущена                             |
| [ADR](terms/adr.md)                                     | Артефакт, который фиксирует значимый Architecture Decision: контекст, выбор и последствия                                                                                          |
| [Architecture Decision](terms/architecture-decision.md) | Выбор между альтернативами на уровне системы или организации: что делать и почему                                                                                                  |
| [Architecture Solution](terms/architecture-solution.md) | Конкретная реализация принятых выборов или бизнес-задачи: как сделать технически                                                                                                   |
| [Отказ](terms/failure.md)                               | Система в целом перестала предоставлять требуемый сервис конечному пользователю — сбои не удалось удержать внутри                                                                  |
| [Сбой](terms/fault.md)                                  | Отклонение компонента от заданных рабочих характеристик; локально, не обязательно останавливает систему                                                                            |
| [Технический долг](terms/technical-debt.md)             | Бизнес-проблема, не «недоделка разработки»: сознательный компромисс скорость/качество, который бизнес не закрыл; долг бизнеса перед разработкой                                    |
| [Function](terms/function.md)                           | Часть коллектива с общей специализацией; без оперативного планирования, в отличие от юнита                                                                                         |
| [Stream](terms/stream.md)                               | Объединение юнитов и функций (2–5 юнитов), создающих один продукт или набор тесно связанных продуктов                                                                              |
| [Unit](terms/unit.md)                                   | Условно постоянный состав 5–10 человек с общим оперативным планированием взаимосвязанных задач                                                                                     |
