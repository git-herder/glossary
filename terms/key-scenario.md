# Ключевой сценарий

Верхнеуровневая формулировка ожидаемого изменения для
[стейкхолдера](stakeholder.md): что должно стать возможным или какой результат
должен измениться — в одном-трёх предложениях, языком заинтересованных сторон.

## Определение

Ключевой сценарий описывает класс проблем или ожидаемый исход для
[стейкхолдера](stakeholder.md), а не детали экранов, API или реализации.

Типичные формулировки отвечают на вопрос:

- **какой** пользователь или сторона **что** должна **мочь делать** нового;
- **какой новый результат** от прежних действий должна получать сторона;
- что сторона **не должна мочь** делать или **перестать получать**.

Ключевые сценарии формулируются кратко, языком, понятным
[стейкхолдерам](stakeholder.md), без лишних подробностей. Если user story — это
детальный сценарий конкретного **пользователя** в системе, то ключевой сценарий
это своего рода *stakeholder story*: что должно измениться в мире
заинтересованной стороны.

**Эталонные** ключевые сценарии [Capability](capability.md) живут в
`product-intent/capability/` — они выражают устойчивый класс проблем на
стратегическом уровне.

Scope: `process`.

## Запрещённые смешения

- Не user story: история — детальный сценарий пользователя в продукте на слое
  `specifications` («как [роль], хочу…»).
- Не [реквест](request.md): реквест описывает конкретную инициативу через
  ожидаемый исход и признаки успеха; ключевой сценарий capability — устойчивый
  класс проблем в [замысле продукта](product-intent.md).
- Не критерий приёмки и не тест-кейс.
- Не техническое решение («сделать REST API», «добавить кнопку»).

## Чем не является

- Не постановка для разработки.
- Не описание UI, полей формы или эндпоинтов.
- Не замена [бизнес-цели](business-goal.md): цель отвечает на «зачем инициатива
  в целом»; ключевой сценарий — на «что конкретно должно измениться для
  стороны».
