# Architecture Solution

Конкретная реализация принятых выборов или бизнес-задачи: как сделать
технически.

## Определение

Architecture Solution описывает *как именно* реализовать принятые [Architecture
Decision](architecture-decision.md) или конкретную бизнес-задачу.

Характер: тактический; привязан к задаче или проекту; может меняться в рамках
одного проекта; содержит подробности компонентов, интерфейсов и потоков данных.

Это **класс содержания**, а не отдельный репозиторий. Живые артефакты «как»:

| Содержание solution | Где живёт |
| ------------------- | --------- |
| Диаграммы компонентов и взаимодействий | `architecture` (ArchiMate) |
| API-контракты, постановки | `specifications` |
| Схемы данных | `data-schemas` (миграции) и контракт в `specifications` |
| Технологические детали, план миграции | в артефакте того слоя, к которому относятся; сам *выбор* технологии — [ADR](adr.md) |

Ответственный за согласованность solution — роль AR. Confluence / wiki вне git —
не SSOT.

Solution может опираться на собственные Architecture Decision, относящиеся
только к этому solution. Такие выборы фиксируются обычными [ADR](adr.md) в
репозитории `ADR`; область действия указывают в контексте ADR и ссылками из
модели или спецификаций. Файлы ADR не хранят «внутри» solution и не вкладывают
solution в текст ADR.

Scope: `architecture`.

## Синонимы

- Solution
- Архитектурная реализация

## Запрещённые смешения

- Не путать с [Architecture Decision](architecture-decision.md): decision — *что
  и почему*.
- Не путать с [ADR](adr.md): ADR не описывает реализацию.
- Не отдельный Confluence-документ и не четвёртый репозиторий рядом с
  `architecture`, `ADR` и `specifications`.
- Не называть этот термин просто «архитектурное решение» без Solution / «как».

## Чем не является

- Не лог выборов.
- Не [замысел продукта](product-intent.md).
- Не код в `application`: код отражает solution, но не является им.
