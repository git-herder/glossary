# Capability

Ключевая возможность продукта: класс проблем стратегического уровня, которые
продукт умеет решать, и инструменты для стейкхолдеров — не для конкретных
пользователей или ролей.

## Определение

На русский язык Capability переводится как **ключевая возможность продукта**.

Это класс проблем стратегического уровня и инструменты, которые продукт даёт
**[стейкхолдерам](stakeholder.md)**. Не набор функций для конкретного
пользователя и не набор полномочий роли в программном продукте.

Формулировка — класс проблем, а не список фич. Класс проблем **иллюстрируется**
[ключевыми сценариями](key-scenario.md) capability (stakeholder stories) в
файлах `product-intent/capability/`. Меняется редко по смыслу, чаще — по глубине
реализации.

Трассируется к [бизнес-целям](business-goal.md) и
[стейкхолдерам](stakeholder.md).

Живые статьи capability — в `product-intent/capability/`.

Scope: `product`.

## Синонимы

Леммы «ключевая возможность продукта», «устойчивая способность» и «способность
продукта» считаются синонимами «Capability» и могут использоваться без
ограничений.

- Ключевая возможность продукта
- Устойчивая способность
- Способность продукта

## Запрещённые смешения

- Не [Function](function.md): Function — организационная единица, не способность
  продукта.
- Не фича, не эпик и не user story.
- Не инструмент конкретного пользователя и не набор полномочий роли в
  программном продукте.
- Не «работоспособность» и не «жизнеспособность» системы.

## Чем не является

- Не acceptance criteria и не постановка задачи.
- Не OpenAPI, не ArchiMate и не имена микросервисов.
- Не [ADR](adr.md) и не технический выбор.
